# TSDoc 코드 주석 작성 규칙

이 문서는 TypeScript/React 코드에 적용하는 **문서화 주석 코딩 컨벤션**을 정의한다. C의 Doxygen `@brief`에 해당하는 요약은 `/** ... */`의 **첫 문장**으로 작성한다. 이 규칙은 코드를 설명하는 기준이며, 기존 구현 전체에 즉시 주석을 추가하도록 요구하지 않는다.

## 적용 대상

- `apps/server/src/`: 공개 서비스 함수·클래스·메서드, 인증·게임·DB 관련 복잡한 계약
- `apps/web/src/`: 재사용 React 컴포넌트, Props 타입, 커스텀 훅, 복잡한 상태 전이
- `packages/game-contracts/src/`: 공개 인터페이스·타입·명령·이벤트·상태 데이터

다른 모듈에도 같은 원칙을 적용한다. 단순한 private 함수, 타입만으로 의미가 충분히 드러나는 선언, 자명한 getter에는 주석을 강제하지 않는다.

## 기본 형식

```ts
/**
 * 플레이어의 착수 요청을 검증하고 서버에서 확정된 상태를 반환합니다.
 *
 * @param command - 경기 식별자와 착수 정보를 담은 명령
 * @returns 서버에서 확정된 경기 상태
 * @throws GameError 참가자 권한 또는 착수 규칙 검증에 실패한 경우
 *
 * @remarks
 * 좌표 및 상태 버전 규칙은 실제 공통 계약을 따른다.
 */
```

- 첫 문장: **무엇을 하는지** 짧고 명확하게 작성한다. `@brief` 태그는 사용하지 않는다.
- `@param 이름 - 설명`: 타입만으로 드러나지 않는 매개변수 의미·단위·제약을 설명한다.
- `@returns`: 반환값의 의미나 특별한 반환 조건이 있을 때 사용한다. 반환값이 없는 함수에 기계적으로 붙이지 않는다.
- `@throws`: 호출자가 처리해야 하는 오류 조건을 명시한다. 실제 코드의 예외 동작과 일치해야 한다.
- `@remarks`: 보안, 부작용, 동시성, 불변식, 트랜잭션, 게임 규칙 등 추가 설명에 사용한다.
- `@example`: 사용법이 자명하지 않은 공개 API에 한해 추가한다.
- TypeScript의 타입 선언을 주석에 그대로 반복하지 않는다.

## 대상별 기준

### 서비스·Repository

공개 메서드의 책임, 권한 검증, 실패 조건, DB 트랜잭션 경계, 멱등성, 재시도와 동시성 보장 수준을 필요한 범위에서 설명한다. 구현하지 않은 보장 사항을 단정하지 않는다.

### React 컴포넌트·훅

컴포넌트의 역할, 주요 Props 제약, 상태의 소유 주체, 이벤트 콜백의 의미를 설명한다. 단순 렌더링 함수의 반환 타입을 반복 설명하지 않는다.

### 공통 게임 계약

공개 명령·이벤트·스냅샷 타입의 의미, 좌표 기준, 상태 버전, 서버 확정 여부, 게임별 제약을 실제 `Document/contracts.md`와 일치시킨다.

### 인증·보안

토큰·OAuth state·TOTP·복구 코드의 만료, 검증, 저장·노출 제약 중 코드에서 보장하는 사항을 기록한다. 주석과 예제에 실제 비밀값이나 자격 증명을 넣지 않는다.

## API 문서와의 역할 분리

REST API의 경로, 요청·응답 스키마, HTTP 상태 코드는 기존 **Fastify Swagger/OpenAPI** 및 `Document/contracts.md`를 기준으로 관리한다. TSDoc은 함수의 내부 책임과 비자명한 호출 계약을 보완하며 API 명세를 중복 작성하지 않는다.

## 유지보수·검토

1. 새 공개 API 또는 복잡한 로직을 작성할 때 필요한 TSDoc을 함께 추가한다.
2. 동작·계약을 변경할 때 해당 주석도 같은 PR에서 갱신한다.
3. 리뷰 시 실제 구현, SRS/SDS, `Document/contracts.md`와 모순되는 설명이 없는지 확인한다.
4. 문서화 주석만 추가하는 작업은 기능 변경과 분리한다.
5. TypeDoc 자동 생성 도입은 별도 합의 사항이며, 이 규칙만으로 새 의존성·CI 작업을 강제하지 않는다.
