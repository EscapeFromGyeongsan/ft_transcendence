# 로컬 오목 구현 및 인계

## 현재 범위

카페 로비 → 오목 테이블 → 두 사람 교대 착수 → 승리·무승부·기권 → 새 게임 흐름을 제공한다. 같은 탭에서 라운지로 나갔다 돌아와도 대국을 유지한다. 새로고침 시 초기화하며 영속 저장은 없다. 로컬 게임 로비에서 방을 생성하고 대기실을 거쳐 시작하는 경로도 제공한다.

엔진, 브라우저의 세션 처리, 게임 화면을 분리했다. 로드맵의 온라인·실제 계정·DB 조건은 아직 구현하지 않았다. C1/C2 전체 완료나 MOD-05 평가 통과를 의미하지 않는다.

## 로컬 로비·방 만들기

- 주소: `/#/rooms`. 방 이름·방장 이름으로 방을 생성하고 대기실로 이동한다.
- 방 이름 최대 40자, 플레이어 이름 최대 16자. 양 끝 공백을 제거하며 빈 이름과 같은 방 내 중복 플레이어 이름(대소문자 무시)을 거절한다.
- 방장은 흑돌, 두 번째 자리는 백돌이다. 사용자가 같은 화면에서 두 번째 이름과 각 자리의 준비 상태를 설정한다. 온라인 접속이나 참가자를 모사하지 않는다.
- 두 자리가 채워지고 모두 준비되면 대국을 시작한다. 자리 구성이 바뀌면 준비 상태를 초기화한다.
- 방 목록에 대기·대국 중·종료 상태, 이름·방장 검색, 상태 필터를 제공한다. 방마다 보드와 대국 기록이 독립적이며 로비 이동 시 유지한다.
- 대국을 끝내면 종료 상태, 한 판 더/새 게임으로 재시작하면 대국 중 상태가 된다. 방 닫기는 확인 후 해당 방과 대국만 삭제한다.
- 방·대국은 현재 탭의 메모리에만 존재한다. 새로고침 후 이전 방 주소에 접근하면 로비로 돌아갈 수 있는 안내를 표시한다.

### 확장 경계

`apps/web/src/rooms/types.ts`는 방 메타데이터와 참가자의 id·name·seat·ready를 정의한다. `useLocalRooms.ts`가 생성·자리·준비·시작·종료·삭제를 담당하고, `LocalRoomGame.tsx`가 각 방의 기존 오목 세션을 유지한다. 보드 UI에는 방 이름과 플레이어 표시 이름만 추가했으며 순수 오목 엔진은 변경하지 않았다.

서버 도입 시 로컬 서비스의 방 상태를 API·WebSocket snapshot으로 대체하고, 참가자 식별·방장 권한·준비/시작 검증은 서버에서 수행한다. 현재 id는 로컬 데이터 구분용이며 인증 정보가 아니다. 다인 게임을 실제로 추가할 때 gameType, 정원 정책, 자리·팀 구성, 게임 화면 선택을 확장한다. 정원 값만 바꿔 오목 엔진을 4인용으로 사용하지 않는다.

## 엔진 계약

- `createInitialState(): OmokState`
- `applyAction(state, actor, action): ActionResult`
- actor: `black` 또는 `white`. 로컬에서는 현재 차례를 사용한다. 온라인에서는 **인증된 참가자 ID를 서버가 돌 색상으로 매핑**해야 하며 클라이언트가 보낸 색상을 신뢰하지 않는다.
- action: `{ type: 'PLACE_STONE', x, y }` 또는 `{ type: 'RESIGN' }`.
- 좌표: `board[y][x]`, 0부터 14까지 정수. 화면은 A1~O15로 표시.
- 성공: `{ ok: true, nextState }`. 입력 상태는 변경하지 않는다.
- 실패: `{ ok: false, reason }`. 차례·보드·기록·결과를 모두 유지한다.
- `stateVersion`: 수락한 착수/기권마다 1 증가. 새 경기는 0부터 시작한다. 경기 식별자는 플랫폼에서 별도 부여한다.
- `rulesVersion`: `freestyle-1`. 호환되지 않는 상태를 진행하지 않는다.
- `moves`: 착수 이력. 마지막 원소가 마지막 수다. 기권은 돌을 놓지 않으므로 이 목록에 추가되지 않는다.
- 결과: `null`, `{ kind: 'draw' }`, 또는 `{ kind: 'win', winner, reason, line }`. `reason`은 `five` 또는 `resignation`; 기권 결과의 line은 빈 배열이다.
- 현재 기권 규칙은 **자기 차례에만 기권 가능**이다. 온라인에서 변경할 경우 엔진·UI·계약·테스트를 함께 수정한다.

오목은 숨김 정보가 없어 현재 보드 상태를 그대로 보여준다. 범용 `GameEngine`, 이벤트 추상화, 난수·시간 컨텍스트는 아직 도입하지 않았다.

## 온라인으로 연결하는 순서

1. B·C·D가 `Document/contracts.md`에 실제 인증 ID, matchId, commandId, expectedVersion, snapshot, 오류 형식을 합의한다. 이 문서는 그 합의를 대신하지 않는다.
2. 서버가 패킷 스키마·참가자 권한·버전을 검증하고, 방별 요청을 직렬화한다. 엔진은 서버가 생성하거나 검증해 복원한 상태를 입력받는다. 외부에서 전송한 임의의 보드를 그대로 넣지 않는다.
3. 서버가 엔진을 호출한 뒤 B의 저장 계층에서 명령 중복 방지와 상태/결과 저장을 원자적으로 수행한다. commit 후 D가 확정 상태를 전송한다.
4. `useLocalOmok` 옆에 원격 세션 처리를 추가한다. 화면에는 서버 snapshot을 전달하고, 입력은 서버로 보낸다. 원격 모드에서 브라우저 엔진으로 결과를 확정하지 않는다.
5. 접속 해제·재접속·로딩·오류 표시를 추가한다. 기존 로컬 모드는 독립적으로 유지할 수 있다.

엔진의 `stateVersion`만으로 DB 경합·멱등성이 해결되지 않는다. 저장 및 통신 제어는 B/D의 플랫폼 책임이다.

## 두 번째 게임 추가

게임별 순수 엔진과 UI 폴더를 별도로 만들고 게임 카탈로그에 등록한다. 현재 `App.tsx`의 경로 선택에도 해당 화면을 연결해야 한다. 카탈로그 등록만으로 자동 실행되는 런타임 플러그인 구조는 아니다. 두 번째 게임의 실제 요구가 드러나면 세션·게임 계약의 공통 부분을 추출한다. 윷놀이 착수 여부는 로드맵의 조건부 승인에 따른다.

## 검증 명령과 기준

- `npm test`: 초기 상태·입력 불변성·차례·범위·중복 착수·4방향 승리·장목·무승부·최종 착수의 승리 우선·기권·종료·규칙 버전.
- `npm run build`: TypeScript 검사와 프로덕션 번들.
- `npm run test:e2e`: 데스크톱/모바일 Chromium에서 로비 진입·한 판·결과·라운지 복귀·재시작·새로고침·키보드·기권·확인 취소·가로 넘침 검사. 방 생성·입력 검증·준비 조건·검색/필터·방별 보드 분리·삭제·새로고침 복구 안내도 확인한다.

로컬 브라우저 검증은 로드맵 T03/T07의 실제 계정·서버·DB 증빙을 대체하지 않는다.
