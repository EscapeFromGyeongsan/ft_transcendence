# 웹·실시간 서버 E2E 확장

추적 이슈: [#76](https://github.com/EscapeFromGyeongsan/ft_transcendence/issues/76).

실행일: 2026-11-09 KST. #27 통합 검증의 후속으로, `test/web-e2e-expansion`에서 실제 API·WebSocket·PostgreSQL을 사용하는 브라우저 시나리오를 확장했다. HTTP/WS 응답이나 경기 결과를 mock하지 않는다.

## 통합 기준과 변경 범위

- 기준: `codex/gomoku-integration`의 `b24ea10` (Draft PR #67).
- 웹: `feat/web-othello`의 `3d06126`까지 병합. 약관·OAuth/2FA·오델로 화면의 원본 PR #71~#73을 포함한다. CSS 파일 끝의 병합 충돌은 기존 스타일과 추가 스타일을 모두 보존해 해결했다.
- 엔진: 통합 기준에 이미 포함된 PR #58의 오델로 엔진을 `apps/server/src/engines.ts`에 등록했다 (#60의 오델로 등록 범위). 오목 등록을 유지한다.
- 라우팅: 실제 브라우저에서 약관 탭 이동 후 뒤로가기가 `about:blank`로 빠지는 현상을 재현했다. 사용자 이동은 `pushState`, 초기 진입·인증/WS 복구·popstate의 주소 보정은 `replaceState`를 사용하도록 수정했다. 대국 경로 복귀 시 오델로 경기 식별자도 최신 상태를 사용한다.
- 모바일: 장식용 glow가 화면 밖으로 넘어가 페이지 가로 폭이 늘어나고 로그인 푸터 링크의 클릭 위치가 어긋나는 현상을 재현했다. 앱 셸의 가로 넘침을 잘라 정상적인 스크롤 폭을 유지하며, 가로 넘침 없음과 일반 클릭으로 약관 열기를 함께 검증한다. 실패 시 스크린샷도 저장한다.

이 브랜치의 PR 기준은 `codex/gomoku-integration`이다. 원본 웹 PR 및 #67의 정식 병합·base 갱신은 별도이며, 이번 검증이 원본 PR 승인이나 #27 전체 완료를 뜻하지 않는다.

## 재현 방법

Node.js/npm, Chromium 및 별도 PostgreSQL 17 검증 DB가 필요하다. 저장소 루트에서 실행한다. 가입·경기 기록이 생성되므로 검증용 서버/DB를 사용한다.

```powershell
npm.cmd ci
npx.cmd playwright install chromium
$env:DATABASE_URL = '<별도 E2E 검증 DB 연결 문자열>'
$env:JWT_SECRET = '<32자 이상의 검증용 임의 값>'
$env:TWO_FACTOR_KEY = '<별도로 생성한 32자 이상의 검증용 임의 값>'
$env:AVATAR_DIR = '<검증용 아바타 디렉터리>'
$env:PORT = '3101'
$env:E2E_PORT = '5183'
$env:CI = '1'
npm.cmd run db:migrate
npm.cmd run test:e2e -- --workers=1 --retries=0 --reporter=line
```

Playwright 설정이 API와 Vite를 시작하고 종료한다. `E2E_BASE_URL`을 지정하면 기존 배포 서버를 대상으로 실행하며 로컬 서버는 기동하지 않는다. 인증 요청 속도 제한과 공유 매칭 대기열을 고려해 이 검증은 worker 1개로 실행했다.

단위·DB 통합 테스트에는 **E2E DB와 다른**, 실제 이름이 `_test`로 끝나는 일회용 DB를 사용한다. 테스트 도우미가 migration을 적용하고 테이블을 초기화한다. E2E 실행이 끝난 뒤 다음 검증을 순서대로 실행한다.

```powershell
$env:TEST_DATABASE_URL = '<별도 단위/DB 통합 검증 DB 연결 문자열>'
npm.cmd test
npm.cmd run build
git diff --check
```

## 실행 환경 및 범위 제한

- Windows / Node.js 26.13.0 / Playwright 1.63.0 / Chromium 153 / 실제 PostgreSQL 17.11.
- 기존 `.env`나 개발 DB를 사용하지 않고 임시 경로의 PostgreSQL 클러스터, 서로 다른 `cafe_e2e_test`·`cafe_unit_test` DB, 임시 아바타 경로를 사용했다. PostgreSQL은 loopback 전용 포트에서 실행했다.
- 첫 브라우저 실행에서 약관 뒤로가기 실패를 재현한 뒤 수정했다. 이후 404 복귀 검증은 로그인 화면의 실제 제목으로 확인하도록 테스트 선택자를 수정했다.
- 최초 전체 회귀를 브라우저와 동시에 실행했을 때 기존 heartbeat 테스트 1개가 시간 초과했다. 해당 테스트의 단독 재실행은 통과했다. 최종 전체 회귀는 브라우저 실행과 분리해 순차 실행했으며 307개 모두 통과했다. heartbeat 코드나 제한 시간을 변경하지 않았다.
- HTTPS/WSS·Docker·서로 다른 두 PC·실 42 OAuth·TOTP 설정 전체·성능 부하·친구·초대·전적 공개 수정·탈퇴는 이번 검증 범위에 포함하지 않는다.
- UI 전적의 1행 확인은 DB 중복 저장/경합의 모든 경우를 증명하지 않는다. 관련 PostgreSQL 통합 테스트와 별도 T05 인수를 함께 확인한다.
