## 인수 차단 결함

### B88-01: 탈퇴 계정이 친구 관계와 요청 대상에 남음

사전 조건: 실제 가입한 A/B, 친구 요청/수락 완료. A가 비밀번호 확인으로 `DELETE /api/users/me`를 호출한다.

기대: 204 뒤 B 목록/요청에서 A가 제외되고, A ID의 새 요청은 `404 USER_NOT_FOUND`.

실제: A=`38`, B=`39`. 탈퇴는 **204**인데 B의 친구 목록이 `{userId:38,nickname:"deleted:38",online:false}`를 반환한다. 같은 ID에 요청하면 **409 ALREADY_FRIENDS**. 남은 관계를 삭제한 뒤 다시 요청하면 **201**로 새 요청을 만든다.

증거: `tests/friends-deletion-acceptance-88.spec.ts`, `friends-deletion-v2.results.json`의 `deleted-friend-contract.json`, 이 문서의 evidence JSON. 이 테스트는 정상 통과로 바꾸거나 skip하지 않고 실패로 유지한다. 기본 Playwright 실행은 별도 HTTPS 인수 파일을 제외하며 전용 설정으로 명시 실행한다.

원인: #89는 사용자 soft delete를 하고 #95는 `deleted_at` 필터·대상 사용자 잠금·탈퇴 transaction의 friendships 정리가 없다. #98의 최신 generation 수정은 관계 변경 알림이 없는 탈퇴를 대신 처리하지 않는다. 원본 담당자에게 활성 대상 조건/잠금, 관계 정리, commit 후 양쪽 알림, 경합 회귀를 함께 요청해야 한다. 이 후보에서 원본 서버 정책을 임의로 바꿔 합격시키지 않았다.

### B88-02: 개인정보 페이지의 문의 방법 누락

`apps/web/src/legal/legal-routing.ts`의 개인정보 4개 절에는 수집/목적/보안/보유·파기가 있지만 연락 방법이 없다. 기준 SRS의 NFR-PRIV-01에 문의 방법이 포함돼 있어 AT-11을 전부 통과로 판단할 수 없다. 운영자가 실제로 받는 이메일/문의 경로를 정해야 한다. 임의 연락처는 넣지 않았다.

GitHub 이슈/댓글 게시 전 확인이라는 사용자 지침에 따라 위 두 결함의 게시 문안만 준비했다. 게시·PR 생성·병합은 하지 않았다.

## 계약 확인이 필요한 항목

- 기준 SRS `349e9e4` 부록 DEC-03은 부재 시간을 **감지 시각부터** 계산한다고 적는다. 최신 문서 브랜치 `origin/docs/sds-a-review`의 SDS 2.6.13은 silent 연결의 **마지막 응답 시각부터** 계산한다. 이번 후보/실측은 SDS 동작이다. 60초 예산이라는 공통 수치만으로 두 문구의 합의가 끝났다고 보지 않으며, 원본 문서에서 기준을 맞춰야 한다.
- 같은 SDS의 과거 20초 무응답 + 검사 주기 추가 지연 설명과 달리 이 후보는 별도 deadline 타이머를 사용한다. 측정 20,918ms를 정확히 20초 이내라는 SLA 통과로 해석하지 않는다. 과거 약 30초 기록과 현재 관측값을 각각 보존한다.
- SRS의 방 준비/시작 단계와 현재 즉시 자동 매칭 시작 구현도 원본 계약에서 정리해야 한다. 해당 차이는 AT-04를 차단한다.

## 재현과 증거 취급

최소 명령 예시는 다음과 같다. 비밀 환경 파일/인증서 준비는 [runtime.md](runtime.md)를 따르고 테스트 DB를 운영 DB와 구분한다.

  E2E_ACCOUNT_DELETION_INTEGRATION=1 \
  npx playwright test --config=config/playwright.acceptance.config.ts \
  'tests/acceptance-88\.spec\.ts$'

후속 파일은 `realtime-acceptance-88`, `two-factor-acceptance-88`, `friends-deletion-acceptance-88` 및 기존 실제 서버 테스트다. 부하/다른 시나리오와 동시에 인증 제한을 소모하지 않도록 배치를 나누며, 배치 사이에는 **자신의 후보 API만** 재시작했다. 제한 값 변경·실패 자동 재시도는 없다.
